## Traps learned in the evening round

These are additional to the twelve below, which stand.

13. **Gating a route turns every unchecked `r.json()` on its callers into a
    rendered lie.** `/api/stats` was gated on 16 August; `/cover` read it without
    `r.ok`, so a truthy `401 {error}` body became the data and the masthead
    printed `undefined` four times. **When you gate a route, grep its callers.**
14. **"Change a value, get an identical PNG" is what a NOT-RENDERED element looks
    like — and also what a DELETED one looks like.** Satori silently paints
    neither an SVG data-URI background tile nor a `radial-gradient`; use
    primitives. But when the card's frames vanished I blamed Satori for dropping
    `border`, and it was my own patch, which had replaced a span up to the next
    JSX marker. **Check the file before blaming the renderer.**
15. **`element.focus()` from script does not match `:focus-visible`.** A
    focus-ring audit written that way reports EVERY control as unstyled. Drive a
    real `Tab`. (Trap 3 below is the sibling of this one and both are real.)
16. **"The tooling isn't here" is a claim to check, not a conclusion.** I shipped
    the social card in a fallback face saying the brand fonts could not be
    loaded. Satori cannot read WOFF2 and `public/fonts` held only WOFF2 — but the
    faces are SIL OFL and Google publishes TTFs. One `curl` fixed it.
17. **When a face changes, re-measure every clipped or `nowrap` box.** Share Tech
    Mono is wider than VT323, so the passport MRZ rendered 1043px into a 978px
    box and `overflow: hidden` clipped the tail — the part encoding the account
    number. Compute from the font's own advance metric.
18. **A `viewport: 0x0` reading means throw the measurement away, not adjust to
    it.** The browser pane collapses; when it does it reports the mobile layout
    at desktop width and every number is wrong.
19. **Calibrate from the distribution, not by eye.** Ruling 8 mapped `conf` onto
    0–99. "Map it to the full range" sounds obviously right and would have
    emptied the stylist — the composite only occupies 0.62–0.92 in practice.
    9,000 sampled looks put the floor at the 27th percentile instead.
20. **A revert-harness patch that hits a COMMENT copy of a string reads as a
    vacuous test.** One revert came back green because `.replace()` found the
    header comment quoting the very typo it was explaining. Re-anchor before
    believing "GREEN — VACUOUS".
21. **`commits/<sha>/status` is NOT the aggregate — it omits every GitHub
    Actions check.** On #257 it returned `success` while `Production build` was
    still `pending`; that check went on to run for 1m44s. It reports the legacy
    *commit status* API (both Vercel contexts) and knows nothing about *check
    runs*. The ritual written after #229 to stop one context being watched was
    itself watching one KIND. **Poll `gh pr checks <n>` and merge only when no
    row says pending** — the ritual below is corrected to match.
22. **A test written where every path returns the same value cannot fail, and
    reads exactly like one that can.** With Supabase unconfigured, every branch
    of `getAuthenticatedUser` answers `null` — so the header assertions in #257
    would all have passed with the bearer regex deleted. The fix is to find a
    discriminator that separates "matched" from "did not" without a network
    round trip: a **malformed `supabaseUrl`** makes `createClient` throw, so a
    matching header rejects while a non-matching one still returns `null`.
    Confirmed by mutation — the `^` anchor SURVIVED before this and was killed
    after. **Ask what the test would do if the line under test were deleted,
    and answer it by deleting the line.**
23. **Two confident bug reports died on inspection, and neither was written
    down as a finding.** "A Supabase outage 500s every authenticated route"
    (`_request` turns network failure into `AuthRetryableFetchError`, which IS
    an `AuthError`, so it comes back as `error` — the gate fails closed) and "a
    null identity degrades to guest" (all four routes checked return 401).
    Both were plausible from the call sites and both were wrong at the source.
    **Read the installed dependency, not the mental model of it** — the answer
    was in `node_modules/@supabase/auth-js`.
24. **A mutation harness can report SURVIVED for a mutation it never applied.**
    Sibling of trap 20, and worse, because it fails in the reassuring
    direction. A `perl` replacement whose escaping was wrong still CHANGED the
    file, so a `diff`-based "did it apply?" guard passed, and two real defects
    were logged as survivors that the assertion does in fact catch. **Guard on
    the expected text landing (`grep -q`), never on the file merely differing**
    — "the mutation ran" and "the mutation is what I wrote" are different
    claims, and only the second one is the test.
25. **A retraction that stops at the handover has not landed.** The deploy
    diagnosis was corrected in this document in the morning while
    `check-deploy-drift.mjs` went on printing *"that is a project setting"* as
    its remediation — and the script is what an agent reads at 9am, not this
    file. #259 moved it and pinned the ORDER of the two sentences, because
    leaving both in the wrong order quietly restores the original advice.
    **When you retract a claim, grep for where it is repeated as an
    instruction.**
26. **`perl -0pi -e` on a UTF-8 file re-encodes the WHOLE file.** Introducing
    one `\x{2019}` into the replacement made perl treat its output as text,
    emit `Wide character in print`, and write every existing `§` as `Â§` and
    every `—` as mojibake — 183 lines changed for a 4-line edit, and
    `iconv -f UTF-8 -t ISO-8859-1` did NOT cleanly reverse it. **Use the
    editing tool for prose, keep `perl -0pi` for ASCII-only source, and treat
    a wide-character warning as corruption until proven otherwise.** Caught by
    diffing against HEAD; the fix was `git checkout HEAD -- <file>` and redoing
    the edits, not repairing the encoding.
27. **A check that carries a COPY of a constant must be pinned to the
    original.** `measure-match-floor.mjs` cannot import `MATCH_FLOOR` — it
    lives inside a route module — so it declares its own `FLOOR = 75`. Change
    the route's constant and the check goes on measuring 75 and goes on
    printing "the floor is a real gate" about a floor the product no longer
    enforces: green, confident, and about nothing. A test now equates the two
    by reading both files. **Whenever a value is duplicated across a boundary
    the language cannot cross, the test IS the boundary.**
28. **A guard written for one direction waves through the opposite one.** The
    tempting change to a floor is to RAISE it, and that starves the page —
    §M4's promise is that a generation never empties. `floor:check` exits 1
    both when the floor rejects almost nothing and when it rejects too much,
    and both were verified by moving it (20 → rejects 0%, 90 → rejects 100%).
    **Ask what the opposite mistake looks like before calling a guard done.**
29. **#262 WAS MERGED OVER A RED CHECK — the third version of one mistake.**
    `Vercel – asilum` read *"Deployment rate limited — retry in 24 hours"* and
    the merge went through anyway, because the polling loop grepped the output
    for `pending` and never looked at the exit code. The morning's ritual was
    corrected for watching one KIND of check (trap 21); this is the same ritual
    failing for watching the TEXT instead of the STATUS. Harm was contained —
    the only undeployed commit is this document, and `deploy:check` correctly
    reports docs-only — but nothing about the loop made that a decision rather
    than luck. **`gh pr checks --watch --fail-fast && gh pr merge …`**: let the
    shell refuse, and the failure mode cannot recur. See §Rituals.

30. **`.catch(() => null)` on a `.json()` is NOT a status guard, and counting it
    as one under-reported this by a factor of four.** My first sweep for trap 13
    found FIVE unguarded reads; the corrected one found **nineteen**. A
    `.catch` handles a PARSE failure, and a `401 {error}` body parses perfectly
    well — it is the one case that needs catching and the one case it does not
    catch. Only `res.ok` or an explicit status comparison counts. **When an
    audit returns a comfortable number, check what it accepted as safe before
    believing it.**
31. **A landing guard must confirm WHERE the text landed, not that it exists.**
    Trap 24 said to `grep -q` for the expected text instead of trusting a diff.
    That is still not enough: a `perl` multi-line substitution inserted my
    mutation at the TOP of the file instead of the target line, `grep -q` found
    the string somewhere and reported success, and the mutation was logged
    SURVIVED when it had never been applied to the code under test. **Assert the
    line, or assert the resulting behaviour — existence anywhere is not
    application.**
32. **A FALSE guard is worse than no guard — it hides the bug it was written to
    find.** The trap-13 detector's status check was `/\.status\s*[=!]==?/`,
    which matched `d.ticket.status === "unavailable"` — a DOMAIN field on the
    parsed body — and declared a genuinely unguarded parse safe. A deliberate
    regression passed a green test. **Scope a guard pattern to the object it is
    about** (`res`/`response`/`r`), and never let a check match the very data
    it is supposed to be protecting you from.
33. **A window around a line attributes it to whatever sits nearby.** The same
    detector was wrong three more ways for one root cause. Endpoints: a read of
    `/api/connect` was blamed on an `/api/moodboard` call eight lines up, and a
    real `/api/profile` read was MISSED behind an `/api/discover` call. Guards:
    a fixed ±8 lines read the NEIGHBOUR's `r.ok`, so fixing one fetch silently
    excused the fetch beside it. **Resolve to the construct that owns the line
    — walk back to its call, and stop the window where the next call begins.**
    Every one of these was found by mutation, none by reading.
34. **A comment can claim what the code does not do, and both read as
    correct.** My own constants test carried *"adding a fourth copy of
    CONTRIB_CAP shows up as a diff on this file"* directly above a record
    keyed on `name=value` — which a third copy does not change. The comment
    was right about what the test SHOULD do and wrong about what it did, and
    only a mutation found the gap. This is the session's most repeated shape:
    `/cover` promising every value is real state while printing `undefined`,
    the drift check instructing a fix its own document had retracted, and now
    a test describing a guarantee it did not implement. **When a comment states
    a guarantee, the mutation that violates it is the test.**

## Rituals

- Build/test: `npm run build` / `npm test`. **System Node is v26.7.0 and both
  pass on it unmodified**; the pinned v20.18.1 is what the launch configs put on
  `PATH`, so leave those alone. Postgres suite:
  `TEST_DATABASE_URL="$DATABASE_URL"` plus `DATABASE_SSL_CA`.
- **`npm run deploy:check` after any merge that touches runtime code.** It is the
  only thing that distinguishes "merged" from "shipped".
- **`npm run triggers:check` before repeating that a deferral has not fired.**
  Needs `set -a; source .env.local; set +a`. Pure reads; exit 1 if one has
  fired, and an unmeasurable trigger counts as fired rather than as fine.
- **`npm run floor:check` after anything that touches the catalog, the stylist
  or `MATCH_FLOOR`.** Same env line. Ruling 8 is a claim about the DISTRIBUTION,
  so restocking can revert it with every test green. Exit 1 both if the floor
  goes inert and if it starves the page.
- Preview: launch config `asilum` (:3458). It runs against the **LIVE database**
  and `next start` serves the **BUILT** app — rebuild and restart to see edits,
  and keep verification read-only unless you intend to write to production.
- `gh pr create/view/checks/list/merge` all work directly; the old `read:org`
  wall is gone. **But the token has no `workflow` scope** — see STEP 2.
- **Poll ALL checks before merging, and let the EXIT CODE decide.** One line,
  and it is the whole ritual:

  ```
  gh pr checks <n> --watch --fail-fast && gh pr merge <n> --merge --delete-branch=false
  ```

  `gh pr checks` exits **0** all-pass, **1** on any failure, **8** while
  pending, so `&&` structurally cannot merge over a red check. ⚠️ Two earlier
  versions of this ritual were both wrong. The `gh api
  repos/.../commits/<sha>/status --jq .state` one-call is **NOT** the aggregate
  — it omits GitHub Actions check runs, and on #257 said `success` while
  `Production build` had not started (trap 21). Its replacement — *"merge when
  no row reads `pending`"* — grepped the TEXT and ignored the exit code, so
  **#262 was merged over a red `Vercel – asilum`** (trap 29). #229 was the same
  mistake a third way. Stop reading the output; read the status.
- **Always `--delete-branch=false`.** Branches are retained; deleting one
  auto-closed PR #2 once.
- A3: verify a merge with `git merge-base --is-ancestor <sha> origin/main`, never
  by the MERGED label.
- Migrations run as the OWNER role: `node scripts/apply-schema.mjs <file>` uses
  `DATABASE_ADMIN_URL`; the runtime `DATABASE_URL` (`asilum_app`) has no DDL.
- Project skills in `.claude/skills/` are binding — load `asilum-ui` before any
  UI change, `asilum-architecture` before backend work, `database-safety` before
  Supabase, `feature-verification` when finishing.
- **Mutation-test every new test file.** Across nine files this session: 96
  mutations introduced, 94 caught, 2 documented *equivalent mutants*. It found
  three tests that could not fail, every one of which read as correct.
