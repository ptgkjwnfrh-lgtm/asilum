## Traps learned 18 August (worth carrying anywhere)

1. **CI applies every migration to a bare Postgres container** — an
   unguarded `REVOKE ... FROM anon` fails there (`role does not exist`).
   Guard pattern: v26 line 38 (DO loop over pg_roles). v31 hit this; v31+
   v32 now carry the guard.
2. **`resolveRequestUser` returns null for an EMPTY claim by design** — the
   client always sends a uid claim which the cookie then overrides. curl
   tests must send a non-empty `user` field alongside the device cookie or
   every request 401s and the route looks broken when it isn't.
3. **`next start` marks the device cookie Secure** — a curl cookie jar will
   not replay it over http://localhost. Send it as an explicit
   `Cookie:` header; that tests the route, not the transport.
4. **`preview_start` on a prod-DB-backed config auto-opens `/`, and the
   feed writes impressions on view** — one anonymous visit's worth of prod
   rows (disclosed; same class as the Aug 17 incident). Use
   `asilum-memmode-verify`, or navigate to `/terms` immediately.
5. **Stripe's sandbox UI renders test keys in PLAINTEXT** — any screenshot
   of that page captures the key. Live-mode keys need a reveal click:
   copy WITHOUT screenshotting the revealed state. Rolling a burned key is
   the owner's click for the same reason (the new key displays on roll).
6. **The auto-mode classifier blocks typing into dashboard config fields**
   (Supabase Site URL) — same protective class as the DB-password rule.
   Owner-only; don't route around it with form_input.
7. **An advisor WARN can be structurally unfixable on the current plan** —
   leaked-password protection is Pro-gated. Check the plan gate before
   queueing a "2-minute toggle".
8. **safeExternalUrl NORMALIZES** (adds trailing slash etc.) — test
   fixtures that exact-match un-normalized URLs fail mysteriously. Match
   semantically (`new URL(u).pathname`).
9. **Two intake laws on purpose:** operator intake is ATOMIC (one bad item
   refuses the batch — prevents operator drift); consented Shopify import
   is PARTIAL with loud skips (bulk store data; sold-out variants land as
   skips by design). Don't "fix" one to match the other.
10. **Stale registers lie like stale comments** (trap 34's cousin):
    OWNER-DECISIONS #9 said "no public intake exists" while the panel had
    shipped Aug 13. Check the surface before building it again.
11. **`gh pr checks --watch --fail-fast` trips on the meaningless vq9p
    red.** The working ritual polls `gh pr checks`, requires `Production
    build` + `Vercel – asilum` both pass, and allows ONLY
    `Vercel – asilum-vq9p` to fail. (Ritual below.)
12. **Shopify products.json carries NO currency** — the operator passes it
    explicitly per import; a CA shop imported as USD is a silent lie.
13. **Webhook/reconcile double-fire is guarded by PRE-state** — notify only
    when the order was not already paid and the event id is fresh. A
    photo-finish race can still double-send ops email at worst.
14. **My own test-fixture bugs cost two red runs**: variants sharing a
    `source_product_id` tripped the duplicate check before the gate check;
    an exact-URL fetch fixture missed the normalized URL. Fixture bugs
    read exactly like code bugs — check the fixture first (trap 22's
    shape: check the mutation/fixture before the code).
15. **(#291 round.) Gate PRECEDENCE reads as a wrong response** — the
    impersonation route answers 403 (sign in) before validating the
    evidence URL, so a curl probing URL validation sees 403 and looks
    broken. Know the gate order before calling a refusal a bug.
16. **sharp renders SVG buffers** — deterministic test images (gradients,
    checkers) come from tiny inline SVGs, no binary fixtures committed.
    A recompressed JPEG of the same picture stays within the dHash flag
    threshold (≤6 bits); unrelated compositions land >10 — measured in
    the test, not assumed.
17. **Flag, never judge** — all three anti-impersonation screens
    (name collisions, image collisions, domain proof) only ATTACH findings
    for the human. The one design temptation to resist forever: an
    auto-reject "just for the obvious ones." Feature G's law has no
    obvious-ones exception.
18. **(#293 round.) `getItems` returns a MAP** — iterating it as an array
    yields [id, item] pairs and every field reads undefined, silently.
    The titles join shipped broken for one build because of it.
19a. **(#295 round.) The browser pane's mobile preset EMULATES TOUCH** —
    after `resize_window` to 375, mouse clicks translate to touch and
    Stripe's radio rows stop responding (30s click timeouts that read as
    "pane stuck"). Reset to the desktop preset before driving external
    checkout pages; verify mobile with read-only checks.
19b. **The morning's $240 test payment is REFUNDED** (re_3U6EJe…, test
    money) — it was the proof body for the refund seam. Stripe's test
    dashboard shows both the charge and its refund.
19. **A local verify server MUST export SITE_ORIGIN** or every checkout
    session's return URLs point at PRODUCTION (the canonical-host law
    forbids request-derived origins — correct in prod, surprising on
    localhost). Fixed in the launch config, never in code; the memmode
    entry now carries it.
