The four blockers as they stood when this was written — **all four are now
fixed (#381, #382, #383)**; kept because the shape of each is worth knowing:

1. **`acceptRequest` / `declineRequest` take no pair lock and no state guard.**
   Accept racing decline can leave a conversation in a state neither caller
   chose.
2. **`now()` is the TRANSACTION START time in Postgres**, and the pair advisory
   lock is taken *after* `BEGIN`. A transaction that waits on the lock stamps
   `last_activity_at` and `created_at` from before it waited — so the keyset
   ordering the inbox and the thread both depend on can go backwards.
3. **`declineRequest` never checks the caller is the RECIPIENT**, only that they
   are *a* participant, and its UPDATE has no state predicate.
4. **Search is a block-detection oracle.** `findAddressees` and
   `resolveAddressee` exclude anyone who blocked the caller, so a person
   vanishing from search *tells you they blocked you* — defeating the deliberate
   ambiguity built one file over, where P0001 and P0002 are collapsed on purpose
   so exactly that cannot be learned. **This one is a design error of mine, not
   an oversight:** I wrote the ambiguity rule and then broke it with the search
   predicate three PRs later. Fixing it needs a ruling — see the parked list.

## § THE MAIL DESK (#371–#378) — the bulk of the day

Complete except attachments. Search-to-start, threads, a requests inbox,
per-account blocking, mute, unread, typing, read receipts, reactions, unsend,
per-conversation media consent, idempotent sends, pagination on both surfaces.

**The design pass came first** (`wf_86327ec9-4e2`, 13 agents). It produced a
14-table design; the red team returned 9 blockers against it. **I cut the design
rather than patching it** — `docs/dm-core-decisions-2026-08-23.md` records what
went and why. Three shapes caused most of the blockers:

1. **A pinned copy of a fact that lives elsewhere** (`dm_settings.account_kind`
   duplicating `account_kinds.kind`) — four blockers. Cut; the trigger joins
   live. *A copy of a fact is a second fact.*
2. **Denormalised counters** — drift in both directions. Cut; unread and the
   inbox preview are DERIVED. This paid off twice later: unsend needed no
   recompute, and there was no counter to backfill.
3. **Media** — five blockers, all in a pipeline that is switched off anyway.

### The laws, all triggers
The route is not the only writer — the desk, a migration and future jobs write
too — so a law living in one caller is a convention, and v38 is the local proof
that conventions fail silently.

1. A per-account block stops delivery **both directions** (v40), extended to
   reactions (v42) and to **presence** (v44).
2. A passport may close its DMs; a **business may not**. The kind is read LIVE.
3. **One knock** until the request is accepted, counted in the trigger.
4. Both-sides per-conversation media consent — **state only**, no pipeline.
5. Activity signals are **reciprocal**: off stops you emitting *and* seeing.
6. **Mute silences only the badge** — never delivery, never unread-inside, and
   undetectable by the other party.
7. Search finds only people who **published a profile room**; addressing is by
   handle and the account uuid never reaches the client.

### `lib/db/dm.js` has NO memory mirror, deliberately
It throws `MessagingUnavailable`. A JS mirror of a trigger is a second
implementation of the law that the unit suite would then certify while
production runs the first — the failure `lib/db/production.js:2645` already
records. **Do not add one.**

## ⚠ Traps learned 23 August (75–93)

75. **ADR-002 already decided the DM identity, and #368 violated it.** There are
    seven ADRs in `docs/adr/` and I had opened none. Social/trust domains key on
    the BARE auth uuid; device identities can never hold one. **Read the ADRs
    before designing.**
76. **Read `CONSTITUTION.md` §4 and `OWNER-DECISIONS.md` before building a named
    feature.** DMs were constitutionally BLOCKED (Phase 7 + a full safety stack),
    and age policy was a co-blocker. The owner can approve their own
    constitution — but the approval must be RECORDED.
77. **A chained `git checkout -b X && …` that fails validation never made the
    branch.** Four commits went to local `main`. Check `git branch
    --show-current` after any chained checkout.
78. **Literal control characters in tests become tautologies when stripped.**
    `assert.equal("ab" → "ab")` became `assert.equal("ab","ab")`. Write
    them as `\u` escapes — in source regexes too, or every heredoc containing
    the file fails input validation.
79. **`lib/db/dm.js` imports `./index.js` UNSUFFIXED**, so a `?dmN` pool in a
    test never reaches it. Store tests must sit ABOVE the board/ticket test, on
    the default pool, ending NOTHING.
80. **Two sibling JSX branches rendering the same panel tear it down.** One
    element; switch the contents.
81. **A header-anchored panel hangs off the left on mobile.** Anchor to the
    viewport ≤760px.
82. **`.click()` does not fire `mousedown`**, so it never triggers
    `useClickAway`; and the shell re-issues a device identity on mount and calls
    `setUid`, flipping any `sb-` identity a browser test pins.
83. **Accepting a raw account id in `send` skips the whole search defence.**
    Address by handle, resolved through the same predicate the search applies.
84. **There is no `visually-hidden` utility in this codebase** — a
    screen-reader-only span renders. Use `aria-label`.
85. **My own reciprocity test asserted the wrong half.** Signals off stops you
    EMITTING as well as seeing; emitting is the primary effect.
86. **An open emoji field is a covert text channel.** A stranger held to one
    message could spell sentences a glyph at a time. The palette is a law table
    granted SELECT-only.
87. **The inbox preview kept quoting an unsent message** — a blank line under
    someone's name forever.
88. **Backticks inside a JS template literal close the string.** I wrote them in
    a SQL comment inside one.
89. **An unasserted `.replace()` is a no-op that reports success.** This is the
    one that hurt: a `.replace()` whose anchor did not exist silently dropped
    both the handle fix and the muted badge from #377, and **shipped a crash**.
    ALWAYS assert the anchor.
90. **A hand-written fetch stub agrees with the bug.** My browser check passed
    because I authored the stubbed response shape from the CLIENT's side. Only
    comparing the two real halves catches a wire mismatch — see the contract
    test in `tests/dm.test.js`.
91. **`requestSubject` takes ONE argument.** `requestSubject(req, me)` silently
    discarded the account, keying every DM quota on the device cookie. House
    pattern is `me || requestSubject(req)`.
92. **When a law gains a new enforcement point, re-check every surface OLDER
    than the law.** v40 blocked messages, v42 extended it to reactions, and
    v41's activity signals — written between them — never got the predicate.
    Each feature was correct the day it shipped.
93. **A migration `DELETE` sweeps only what exists when it runs.** It cannot
    clear state for an event that happens afterwards.
