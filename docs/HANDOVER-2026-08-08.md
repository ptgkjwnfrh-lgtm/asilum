## Laws learned — binding

1. **A test that never leaves the file it guards cannot catch a disagreement between two files.** `dense-tags.test.js` asserted `fitLabel(-1) === "runs-small"` — it tested that the function does what the function does, and locked in an inversion for months. Every bug this session lived in a gap *between* two modules that each looked correct alone.
2. **A test asserting the benign case passes against the bug.** `E4` asserted `truncated === false` on a near-empty identity. It passes against broken caps and fixed caps equally. **Before trusting a guard, revert the fix and watch it fail.** I did this for every test I wrote this session; three of my own drafts were wrong and were caught this way.
3. **Placeholders rendered through the same code path as findings become fabricated findings.** The observation tracker seeded three real aesthetic names into `useState` and rendered them identically to measured data.
4. **mem and Postgres are one system with two implementations, and mem is the one being exercised.** Preview deploys, local dev and ~470 of 480 tests run mem. A divergence ships green. Three Round A bugs were this.
5. **A control that reports success without checking the response is worse than no control.** `postJSON` returns a fetch; fetch does not throw on 4xx. Two features (`muteTag`, the observation toggle) looked like they worked and did nothing.
6. **A declared criterion that is never evaluated must be loud.** A battery may not print PASS for something it did not run.
7. **When a fix makes a red light green, ask whether the instrument changed or the world did.** My first r15 control returned CALIBRATED in both worlds — because it let a control put weight 60 on the *ad* bridge, tanking itself and inflating the arm by subtraction. Discarded, not shipped.
