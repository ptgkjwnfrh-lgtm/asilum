## 1. What the owner asked, and what did not move

"i give you freedom to go passed the constitution to make asterisk app
management agent" → "all three": the steward should **act** on its own
findings, **run** on a schedule and report movement, and **decide** inside a
declared boundary. The constitution's read-only rule for the steward is set
aside for this — recorded in `docs/steward-boundary-2026-09-03.md`.

Two rails were kept, and the owner's "all three" accepted them:

* **No faking.** Nothing the hands do produces a fact the catalog did not
  already hold. A piece that cannot be shown honestly is *held*, never given
  an invented price.
* **A hard stop before anything irreversible.** Source-of-truth deletes,
  money, mail, access, DDL are `never`, by name. No flag unlocks them.

## 6. Traps learned today (110–116)

* **110** — a matcher that matches nothing passes everything. `schemaVersionsFrom`
  saw one file (`schema-v2.sql`) in a directory that grew from thirty-seven to
  fifty schema files across the steward's whole life. Anchor matchers on a real
  file in a real directory, never only on a fixture list.
* **111** — **two sessions can share ONE working tree.** The twin's `git
  checkout` was refused only because it would have overwritten my uncommitted
  `checks.js`; that refusal is the only reason the work survived. Commit early,
  or `git worktree add`. A `node_modules` symlink inside a worktree is a
  hazard for two reasons that are **not** `git worktree remove`: a checkout can
  write the link into the index and the tree (#422 did — trap 114), and on
  macOS `rm -rf node_modules/` **with a trailing slash** resolves the link and
  deletes the real directory. `git worktree remove` (with or without
  `--force`), `git clean -fdx` and `rm -rf node_modules` without the slash all
  unlink the link only; the target survives (scratch-repo proof on git 2.39.5,
  4 Sep). `ListAgents` shows the peer; `SendMessage` reaches it; it replies in kind.
* **112** — a stacked PR whose base branch is deleted on the parent's merge is
  auto-CLOSED (#417: `base_ref_deleted` then `closed` one second after #416's
  `--delete-branch`). With the base gone it is deadlocked: `gh pr reopen` fails
  (`Could not open the pull request`) and `gh api -X PATCH …/pulls/N -f base=main`
  fails (422 `Cannot change the base branch of a closed pull request`) — both
  tried, both refused. The only way out is to restore the deleted base branch
  first ("Restore branch" on the parent PR, or push the ref back) — not proven
  here, the push had no local ref to send — so #417 was recreated as #421 from
  the same head branch. Retarget dependents to main **before** merging the
  parent; never `--delete-branch` with a dependent still based on it.
* **113** — `gh pr edit --base` needs `read:org`, which the stored token lacks.
  `gh api -X PATCH repos/OWNER/REPO/pulls/N -f base=main` works with `repo`.
* **114** — #422 committed a `node_modules` symlink. Any checkout or merge of a
  ref carrying it makes git write the link **over the real, ignored
  directory** — `node_modules` becomes a link to itself and the modules are
  gone (it happened three times today). Fixed by #424. Recovery:
  `rm node_modules` (the link only) then `npm ci` (cached, seconds).
* **115** — a chained `git checkout X && … && git commit && git push` whose
  checkout is **refused** runs the rest on the current branch: a docs-only
  commit landed on main with a wrong message (`14c2255`, reverted in
  `95cdaf3`). Guard every commit: `[ "$(git branch --show-current)" = X ] || exit 1`.
* **116** — a **local** branch ref can be stale and still carry the symlink;
  `git checkout main` at `95cdaf3` wrote the link and the following pull
  removed it. `git fetch` and `git ls-tree <ref> node_modules` before any
  checkout in this tree. Only five commits in the whole graph still contain
  it: on `main`, exactly `9cfdf01` (#422), `14c2255` and `95cdaf3` — nothing
  before #422 and nothing from `d95b5d5` (#424) onward; the merge commit
  `8b55393` inside `steward/hands` history (removed there by `27ce5b1`, so the
  branch tip is clean); and `5cde9b0`, the tip of the surviving remote branch
  `origin/docs/the-backlog-is-empty`.
* **117** (the twin's, from #425) — a source-level regression test that greps
  for the fixed line can match **the comment explaining the fix**, which
  quotes the same code; it passed with the bug put back. Strip comment lines
  before asserting on source, and prove the test red once. (Same family as
  trap 64.)

Rituals that held: pull main before branching; merge = `gh pr checks <n>
--watch --fail-fast && gh pr merge <n> --squash --delete-branch=false`;
migrations via `node scripts/apply-schema.mjs supabase/<file>` **after** the
PR merges (it loads `.env.local` itself and refuses the app-role URL); verify
production through the Browser pane, never curl; the Vercel CLI is not
installed here — env vars are set in the dashboard.
