# HANDOVER — 3 September 2026: the steward gets hands

`docs/HANDOVER.md` is the permanent front door; this is the dated record of
one day's change. Read `docs/steward-boundary-2026-09-03.md` for the decision
itself — this page is what happened, in the order it happened, and what is
still open.

## What the owner asked

"make asterisk app management agent … all three": the steward should **act**
on its own findings, **run** on a schedule and report movement, and **decide**
inside a declared boundary. The constitution's read-only rule for the steward
was set aside for this. Two rails were kept and the owner's "all three"
accepted them: **no faking** (nothing the hands do produces a fact the catalog
did not already hold) and **a hard stop before anything irreversible**
(source-of-truth deletes, money, mail, access, DDL — all `never`, by name).

### A defect found on the way

`schemaVersionsFrom` matched only a bare `schema-vN.sql`. Every migration
since v5 is named (`schema-v49-tag-facets.sql`), so of forty-odd files it saw
one (v2) and the ledger check compared production against nothing for the
whole life of the steward. v49 was merged, applied to nothing, and reported
"ok at v48". Fixed; `tests/steward-hands.test.js` anchors the matcher on the
real directory. Trap 110: **a matcher that matches nothing passes
everything — anchor it on a real file.**

## The twin

A second session (`noemosallowed-25`) worked the same checkout during this
build and merged #415–#421. Two lessons it wrote down that hold for anyone
here: the two sessions **share one working tree** — commit before the other
switches branches, or use `git worktree`; and a stacked PR whose base branch
is deleted on the parent's merge is auto-closed and cannot be reopened
(#417 → recreated as #421): retarget dependents to main **before** merging
their parent, and never `--delete-branch` with a dependent still based on it.
