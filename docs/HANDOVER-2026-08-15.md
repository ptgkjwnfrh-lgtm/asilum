## ⚠️ THE ONE THING THAT IS BROKEN RIGHT NOW

**Custom SMTP is enabled in Supabase and it FAILS. Password reset emails are
currently NOT being delivered at all.** This is a live user-facing regression
introduced in the last twenty minutes of the session — it must be the next
session's first job.

### Exactly what is wrong

Supabase auth log, `2026-08-15T02:31:20Z`:

```
"error": "535 \"Authentication failed: The provided authorization grant is invalid, expired, or revoked\""
"error_code": "unexpected_failure"
"status": 500
"path": "/recover"
```

SMTP **535** = the credentials were rejected by SendGrid. The username is
correct (`apikey`, the literal string), so **the password stored in Supabase is
not a valid SendGrid API key**.

### Why, almost certainly

**Chrome's password manager autofills Supabase's SMTP password field.** This was
observed *twice*, directly: the field arrived pre-populated with dots, and the
Username field arrived containing `*ASILUM magazine` — the signature of a saved
login being injected into the form. The field was cleared both times, but
autofill repopulates on re-render, so the value that got saved was very likely
the injected credential rather than the pasted key.

The first save attempt did not persist at all (a cold reload showed the toggle
back **off**). The second save persisted — verified by cold reload — but
authenticates with the wrong secret.

### The fix, in order

1. **Delete the existing key.** SendGrid → Settings → API Keys → `*ASILUMmagazine`
   (ID `m-GRcyYuQfCCsiowfE1B-A`). Its value is unknown and possibly never
   correctly transferred; there is nothing to preserve.
2. **Create a fresh key**: Create API Key → name it → **Custom Access** →
   scroll to **Mail Send** → drag that row to **Full Access** → leave every
   other row at No Access → **Create & View**. Copy the `SG.…` value; it is
   shown exactly once.
3. **Defeat autofill before pasting.** Options, best first:
   - In Chrome, turn off password autofill for `supabase.com`, or use a
     private window signed into Supabase.
   - Or: paste into the field, then **verify the field actually contains the
     key** before saving (a `SG.`-prefixed value is ~69 characters; the
     autofilled junk will be a different length).
4. Supabase → Authentication → Emails → **SMTP Settings**, paste into
   **Password**, press **Save changes**, wait for the green toast.
5. **Verify with evidence, not the toast** (the toast lied once already):
   - Cold-reload the page; the toggle must still be on.
   - Trigger a reset from `/profile`.
   - Check Supabase auth logs for `"event":"mail.send"` with
     **`"mail_from":"asilum@asilummagazine.com"`** — if it still says
     `noreply@mail.app.supabase.io`, custom SMTP is not in effect.
   - Check SendGrid → Activity → **Email Logs**; the message must appear there.

### Escape hatch

If the browser form keeps fighting, Supabase's SMTP config can be set through
the **Management API** (`PATCH /v1/projects/{ref}/config/auth`, fields
`smtp_host`, `smtp_port`, `smtp_user`, `smtp_pass`, `smtp_admin_email`,
`smtp_sender_name`) with a personal access token, bypassing autofill entirely.
The owner must create that token; Claude may not.

### If it cannot be fixed quickly

**Turn "Enable custom SMTP" OFF.** Supabase reverts to its shared sender, which
worked — deliverability is mediocre but password reset functions. A broken
custom SMTP is strictly worse than the default.

## Traps learned this session (all cost real time)

1. **A bare `catch {}` that hides a typo is not error handling.** The reset-error
   fix silently did nothing three times because it lived in `ProfileAccess`,
   where `setTab` is not in scope — the `ReferenceError` was swallowed. It also
   sat behind `getSupabase().then()`, which it never needed. URL truth is
   synchronous; read it synchronously, in the component that owns the state.
2. **A test can only catch a bug in the backend it runs against.** A guard for a
   Postgres-only divergence was written as a mem test, passed with the fix
   reverted, and proved nothing. It belongs in `tests/postgres-integration.test.js`.
   Verified both directions against live.
3. **A green toast is not persistence.** Supabase's SMTP form reported success
   and saved nothing. Always cold-reload and re-read.
4. **Browsers fight credential forms.** Chrome autofilled Supabase's SMTP
   password twice, and clobbered the Username field with a saved login.
5. **Squarespace demands a passkey tap per editing session** — one tap covers
   several consecutive record additions, but the prompt returns. SendGrid's
   "Automatic Setup" is **GoDaddy-only**, so Squarespace must be done by hand.
6. **DNS propagation beats the Verify button.** SendGrid's first Verify failed
   and the second succeeded with no change in between. Confirm with `dig`
   against `8.8.8.8`/`1.1.1.1` before clicking, then just retry.

Still in force from before: every `supabase/schema-vN-*.sql` must insert its
version into `app_schema_migrations`; never export `DATABASE_URL` globally when
running tests (use `TEST_DATABASE_URL`); never force oversized viewports on the
shared preview pane.
