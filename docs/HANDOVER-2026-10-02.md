## 1. What Stage C is (the brief, condensed to the laws)

**§3 Messages.** Familiar Instagram/iMessage patterns, but the owner's
**one-hour edit and one-hour unsend** rules override those apps' limits.
Text limit = **1,000 grapheme clusters** (configurable product default) plus a
**byte limit**; enforce length, sender identity, membership, edit version and
the hour **on the server**; character counter near the limit; edits labelled
*Edited*; unsend = tombstone, content and its search index gone from both
ordinary views (no promise of recalling copies already seen). **Clear
history is per viewer**: advance that viewer's hidden-history boundary, the
other copy untouched, a new message reintroduces the conversation without
restoring the history; **the other participant is told once per clear,
neutrally** (the owner's requested behaviour — keep the handler configurable;
the brief's own recommendation, for founder review, is to suppress it). DM
search syntax: `*handle` → conversations; `words` → messages across the
viewer's conversations; `*handle: words` → messages with that passenger;
`"quoted"` → exact phrase; typographic apostrophes normalised; exact matching
is the default; results carry passenger, excerpt, time, jump-to-message; only
what the viewer may see, after their clear cutoff, never unsent content; **no
LLM sees a DM to search it**. Rate-limit sends, searches, edits, notification
creation. Media pipeline: authenticated bounded upload, inspect real bytes,
pixel/format validation, orientation applied, EXIF+GPS stripped, scan,
thumbnail (320px) + display (≤1600px long edge, WebP ≈ q78), 10 MB upload /
40 MP decode defaults, **dedupe only inside one authorisation boundary**,
private buckets + short-lived authorised URLs re-checked on every load,
**after six calendar months stop auto-loading the full image** ("Archived
image · Tap to load", separate Save image), and an honest answer on whether
a storage tier actually saves money.

**§4 Sharing passengers.** A profile shared in a DM = compact overview-style
card (Passport picture, handle, public bio), DM-only, grants no editorial
overview. Sharing can be switched off in Settings; when off, **block
server-side** and show the owner's exact words:

```
*this passenger does not want their profile shared

:Connect with them to get to know them more
```

Re-check visibility, blocks and permission **when the card is viewed**; share
the entity id + safe public fields, never a frozen copy of a private bio; an
inaccessible profile renders an unavailable card. Notify the shared passenger
**without sender or recipient**; dedupe retries, rate-limit; recommended for
founder review: delayed aggregate notices. Existing shares cannot defeat a
later visibility change.

**§8 Wardrobe and gifting.** Wardrobe lives in Account; confirmed acquired +
self-uploaded owned pieces; provenance shown (purchase record / self-added /
digitally transferred). Cover Flow stack **plus** Grid/List, reduced motion,
direct lookup; every gesture has a button. Detail: seller/source, labelled
size, Size Engine estimate with uncertainty, cost where known, tags,
designer/house links, Share, Gift — private cost/order/address never leaks
through a share preview. **Gift = pending digital transfer** to a resolved
passenger; confirm recipient; recipient must accept; acceptance **atomically**
moves the active wardrobe entry and records a transfer event; sender keeps the
private receipt, loses the card; decline/cancel/expiry leaves ownership
unchanged; row locking or optimistic version + idempotency + recipient
authorisation + a pending-transfer lock so one entry can never go to two
people. Both parties see: *"Digital wardrobe transfer. Physical delivery is
not verified by ASiLUM."* No blockchain.

**§14 release checks that belong to C:** scoped DM search cannot reveal
another user's messages, cleared history, or unsent content, and a forged
viewer id changes nothing; edit/unsend at 59:59 works, at 60:00 fails, a
conflict/offline retry cannot reset the window; sharing a disabled/private/
blocked profile is refused server-side **including existing cards**;
concurrent gift acceptance cannot double-give; six-month images show
previews, explicit load, authorised retrieval.

## 4. Decisions already taken (do not re-derive)

- **Refuse, never truncate** — the composer and the route agree through one
  pure function (`bodyRefusal`); the DB keeps the byte ceiling it can enforce.
- **Two limits, both real**: 1,000 graphemes is the product default the owner
  named; 8 KiB is the ceiling a grapheme count cannot game.
- **One hour** for both edit and unsend, measured from `created_at` by the
  server (`clock_timestamp()` in the trigger, `now()` in the UPDATE); the
  client's clock is never consulted.
- **Edit version is optimistic**: a stale client's edit is refused, not merged.
- **Clear is a boundary id, not a delete**; the peer's notice is the owner's
  requested behaviour, the suppression is a recorded recommendation.
- **Search is deterministic** (parser in `lib/dm.js`), curly quotes folded on
  both sides, exact by default, never through a model.
- **A profile card stores an id, renders live**; the refusal copy is the
  owner's string byte for byte, and it is also the answer when the target
  blocked the sender (no block oracle — same ruling as #383 for search).
- **Media dedupe is per conversation**, never global.
- **Memory mode refuses DM law** rather than re-implementing it (the laws
  live in Postgres triggers, proven in `tests/postgres-integration.test.js`).

## 5. Traps found on 1–2 October (new ones only; the older numbered traps
live in the memory files and the September handovers)

1. **The dev server reads PRODUCTION and the ledger is at v53.** Any SQL that
   names a v56–v59 column or table 500s live (`relation
   "listing_status_events" does not exist` happened). Probe with
   `hasRelation` / `hasColumns` (cached), fall back, and let the UI say
   "needs schema vNN applied" instead of failing the request. Done for v57
   and v58; **v56 on `market/ebay-bulk-feed` still lacks it** (`upsertFeedItems`
   names `source_observed_at`) — add before #479 merges.
2. **A test can assert the old law.** `tests/dm.test.js:176` asserted
   truncation at BODY_MAX; the moment `normalizeBody` stopped slicing it went
   red. When a constant changes meaning, grep the tests for its name first.
3. **`bodyRefusal` returns null on success** — `x.code` on it throws. Assert
   `equal(x, null)`.
4. **Grapheme ≠ byte**: 1,000 family-emoji clusters are 18,000 bytes. A test
   that only counts graphemes will pass a body the DB rejects.
5. **`scripts/.vibe-sweep.json` is dirtied by the gate run** — `git checkout
   -- scripts/.vibe-sweep.json` before every commit.
6. `lib/db/production/editorial.js` imports from `../index.js`, not
   `../core/pool.js`; a regex replace aimed at the pool import missed.
7. `STATUS_WORD.available` was `""` and the span was conditional, so the
   Likes rows showed no status at all — a map value that is falsy hides the
   row that uses it as a condition.
8. A `useCallback` placed above the `useState` it reads throws "Cannot access
   before initialization"; a `useState` initialiser that reads localStorage
   is a hydration mismatch — start empty, adopt in `useEffect` (Stage A/B).
9. A bare state word as a class (`search`) matched an unrelated selector and
   shrank the dock to 140 px (Stage A).
10. `tests/shared-constants` flags any `SOURCE`/`BATCH`/`MAX_EVENTS` const
    that differs elsewhere — name constants specifically.
