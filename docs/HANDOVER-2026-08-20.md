## Traps learned 20 August

20. **A Vercel env var marked "Sensitive" is write-only FOREVER** — even
    Edit shows a blank field. Don't hunt for the old value; mint a new one
    (openssl → pbcopy, never through a transcript), save it in the
    owner's password manager THIS time, redeploy. Env changes apply only
    to NEW deployments — redeploy or the old value serves.
21. **AT ghost-click** (found by ear during claim 12): assistive-tech
    activation can double-fire a click at the trigger's screen position;
    the duplicate lands on whatever now occupies that point — an overlay —
    and dismisses the thing that just opened. Guard EVERY overlay
    click-away with target-is-overlay + a birth window
    (`useOverlayDismiss`). No static test sees this class; only a person
    at a screen reader does — which is why claim 12 existed.
22. **The user's Chrome ≠ the extension's tab group.** Script-created tabs
    land in the MCP group without fronting a window — the owner can be
    staring at a desktop while "the page is open". `open_application`
    fronts Chrome; `Control_Chrome`'s `switch_to_tab` fronts a specific
    tab; only then is a staged page actually ON SCREEN. And dashboard SPAs
    (Vercel) may never render rows into the a11y tree — their own
    authenticated API from the page context (`fetch('/api/…')`) is the
    reliable read.
23. **GitHub's web editor bypasses the token's `workflow`-scope wall** —
    the owner committing via browser activates a workflow the CLI cannot
    touch. The reverse also binds: agents STILL cannot edit
    `.github/workflows/*` (stale header comment in deploy-drift.yml
    stands as evidence).
24. **The first run of a drift-watching workflow judges an in-flight
    deploy** — expect red-that-means-catching-up on activation day; the
    nine-times lesson applies to the watcher's own verdicts.
